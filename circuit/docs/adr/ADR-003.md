# ADR-003: Multi-Breaker Management

## Status: Accepted

**Date:** 2026-04-05  
**Author:** Phenotype Engineering Team  
**Project:** circuit

---

## Context

Applications often need multiple circuit breakers for different services. We need a way to manage them.

---

## Decision

We will provide a **MultiBreaker registry with lazy initialization**:

```
┌────────────────────────────────────────────────────────────────┐
│              MultiBreaker                                     │
│                                                                 │
│  breakers: map[string]*Breaker                                │
│                                                                 │
│  Get(name, config):                                            │
│    - If exists, return existing                               │
│    - If not, create with config and store                      │
│    - Thread-safe with RWMutex                                  │
│                                                                 │
└────────────────────────────────────────────────────────────────┘
```

### Implementation

```go
type MultiBreaker struct {
    breakers map[string]*Breaker
    mu       sync.RWMutex
}

func (mb *MultiBreaker) Get(name string, cfg Config) *Breaker {
    mb.mu.RLock()
    b, ok := mb.breakers[name]
    mb.mu.RUnlock()
    
    if ok {
        return b
    }
    
    mb.mu.Lock()
    defer mb.mu.Unlock()
    
    if b, ok = mb.breakers[name]; ok {
        return b
    }
    
    b = New(name, cfg)
    mb.breakers[name] = b
    return b
}
```

---

## Consequences

### Positive

- **Convenient**: One registry for all breakers
- **Lazy init**: Breakers created on first use

### Negative

- **Global state**: Shared across application
- **No cleanup**: Breakers never removed
