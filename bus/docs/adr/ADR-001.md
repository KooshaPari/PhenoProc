# ADR-001: In-Memory Event Bus Architecture

## Status: Accepted

**Date:** 2026-04-05  
**Author:** Phenotype Engineering Team  
**Project:** bus

---

## Context

The bus library provides an event bus for decoupled communication within a single process. We need to decide on the core architecture for message routing and delivery.

### Requirements

1. **Pub/Sub Pattern**: Multiple subscribers per event type
2. **Non-blocking**: Publishers shouldn't wait for subscribers
3. **Type Safety**: Event types as string identifiers
4. **Context Support**: Cancellation propagation

### Constraints

- Single process only (no network)
- Go 1.21+ with slog support
- Minimal allocations

---

## Decision

We will use **channel-based pub/sub with goroutine per subscriber**:

```
┌────────────────────────────────────────────────────────────────┐
│              Event Bus Architecture                             │
│                                                                 │
│  Publisher                                                      │
│     │                                                           │
│     │ Publish("user.created", payload)                          │
│     ▼                                                           │
│  ┌─────────────────────────────────────────────────────────┐   │
│  │                    EventBus                              │   │
│  │                                                         │   │
│  │  subscribers: map[string][]chan Message                 │   │
│  │                                                         │   │
│  │  "user.created": [chan1, chan2, chan3]                  │   │
│  │  "user.deleted":  [chan4]                               │   │
│  │                                                         │   │
│  └─────────────────────────────────────────────────────────┘   │
│     │                                                           │
│     │  for each subscriber:                                     │
│     ▼                                                           │
│  ┌─────────┐ ┌─────────┐ ┌─────────┐                          │
│  │Subscriber│ │Subscriber│ │Subscriber│                          │
│  │  (goro) │ │  (goro) │ │  (goro) │                          │
│  │   ch1   │ │   ch2   │ │   ch3   │                          │
│  └────┬────┘ └────┬────┘ └────┬────┘                          │
│       │           │           │                                  │
│       ▼           ▼           ▼                                  │
│   handler()   handler()   handler()                            │
│                                                                 │
└────────────────────────────────────────────────────────────────┘
```

### Rationale

| Option | Pros | Cons | Verdict |
|--------|------|------|---------|
| **Channels** | Go idiomatic, efficient | Buffered channel sizing | **SELECTED** |
| Callbacks | Simple | Blocking, no buffer | Rejected |
| Ring buffer | Lock-free | Complex, third-party | Rejected |
| Sync.Map | Standard | Slower, no ordering | Rejected |

### Implementation

```go
type EventBus struct {
    subscribers map[string][]chan Message
    mu          sync.RWMutex
    logger      *slog.Logger
}

type Message struct {
    ID        string
    EventType string
    Payload   interface{}
    Metadata  map[string]string
    Timestamp time.Time
}

func (eb *EventBus) Subscribe(eventType string, handler func(context.Context, Message) error) <-chan error {
    errChan := make(chan error, 1)
    ch := make(chan Message, 100)  // Buffered channel
    
    eb.mu.Lock()
    eb.subscribers[eventType] = append(eb.subscribers[eventType], ch)
    eb.mu.Unlock()
    
    go func() {
        for msg := range ch {
            if err := handler(context.Background(), msg); err != nil {
                errChan <- err
            }
        }
        close(errChan)
    }()
    
    return errChan
}
```

## Consequences

### Positive

- **Go idiomatic**: Uses standard language features
- **Efficient**: Channels optimized by runtime
- **Simple**: Easy to understand and debug
- **Cancellable**: Context propagation

### Negative

- **Buffered sizing**: Fixed buffer size per subscriber
- **Goroutine per subscriber**: Memory overhead
- **No persistence**: Messages lost on crash
- **Single process**: Cannot scale across machines
