# ADR-003: Async Publishing Strategy

## Status: Accepted

**Date:** 2026-04-05  
**Author:** Phenotype Engineering Team  
**Project:** bus

---

## Context

The bus library needs both synchronous and asynchronous publishing options. We need to decide on the API design and implementation for async publishing.

### Requirements

1. **Sync Publishing**: Block until message delivered
2. **Async Publishing**: Fire-and-forget
3. **Error Handling**: Async errors logged, not returned

---

## Decision

We will provide **two explicit methods: Publish (sync) and PublishAsync (fire-and-forget)**:

```
┌────────────────────────────────────────────────────────────────┐
│              Publishing Methods                                 │
│                                                                 │
│  Synchronous (Publish):                                        │
│  ┌─────────────┐                                               │
│  │   Publish   │───▶ Deliver to all channels                   │
│  │             │◀─── Return when done                          │
│  └─────────────┘                                               │
│       │                                                          │
│       │ Returns error if any delivery fails                     │
│       ▼                                                          │
│  Caller blocks until all subscribers receive                   │
│                                                                 │
│  Asynchronous (PublishAsync):                                   │
│  ┌─────────────┐                                               │
│  │PublishAsync │───▶ Spawn goroutine                            │
│  │             │◀─── Return immediately                          │
│  └─────────────┘                                               │
│       │                                                          │
│       │ No return value, errors logged                         │
│       ▼                                                          │
│  Goroutine handles delivery in background                       │
│                                                                 │
└────────────────────────────────────────────────────────────────┘
```

### Implementation

```go
// Publish delivers synchronously
func (eb *EventBus) Publish(eventType string, payload interface{}, metadata map[string]string) error {
    // Direct delivery
    return eb.deliver(eventType, payload, metadata)
}

// PublishAsync delivers in background
func (eb *EventBus) PublishAsync(eventType string, payload interface{}, metadata map[string]string) {
    go func() {
        if err := eb.deliver(eventType, payload, metadata); err != nil {
            eb.logger.Error("async publish failed", "type", eventType, "error", err)
        }
    }()
}
```

---

## Consequences

### Positive

- **Clear intent**: Caller chooses sync vs async
- **Flexibility**: Both patterns available
- **Error visibility**: Async errors still logged

### Negative

- **API surface**: Two methods instead of one
- **Async fire-and-forget**: Errors not handled
